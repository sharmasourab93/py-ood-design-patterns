# SOLID Principle

SOLID is a group of five design principles used to build systems that are easier to change, extend, and test. Each principle in this repository is documented with code-centered examples.

## Principles Covered

- [Single Responsibility Principle](single_responsibility_principle/README.md)
- [Open/Closed Principle](open_close_principle/README.md)
- [Liskov Substitution Principle](liskov_substitution_principle/README.md)
- [Interface Segregation Principle](interface_segregation_principle/README.md)
- [Dependency Inversion Principle](dependency_inversion_principle/README.md)

## Quick Mental Model

- `S`: one unit, one main reason to change
- `O`: extend behavior without rewriting stable code
- `L`: child types should behave like valid substitutes for parent types
- `I`: clients should depend only on the methods they actually need
- `D`: high-level policy should depend on abstractions, not concrete details
